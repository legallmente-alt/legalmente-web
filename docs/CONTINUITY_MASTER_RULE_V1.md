# LEGALMENTE — Regla Maestra de Continuidad

## Un regalo para quienes sigan construyendo

**Autor:** Manus AI  
**Estado:** AUXILIAR / NO CANÓNICO  
**Propósito:** conservar la inteligencia de LegalMente más allá de una conversación, una persona o un agente.

> LegalMente no es un archivo de leyes. Es una forma ordenada de reconocer cuándo una conducta humana se convierte en una relación jurídicamente relevante, qué puede exigirse, qué no puede pactarse, qué falta saber y cuál es la siguiente pregunta prudente.

## La regla maestra

Cada nueva pieza de LegalMente debe recorrer esta secuencia:

> **Vida humana → conducta observable → relación → objeto → tiempo → evidencia → territorio → regla → alcance → límite → pregunta → acción prudente.**

Si una pieza no puede recorrerla, todavía no está lista. No se corrige agregando información al azar; se corrige identificando el vínculo que falta.

## El motor humano-jurídico

El motor no intenta conocer todas las historias posibles. Reconoce patrones estructurales y los combina con las variables que cambian su significado.

| Variable | Pregunta esencial |
|---|---|
| Conducta | ¿Qué hizo, dejó de hacer o intenta hacer la persona? |
| Relación | ¿Quién está frente a quién y qué posición ocupa cada parte? |
| Objeto | ¿Qué se entrega, promete, firma, paga, usa o reclama? |
| Tiempo | ¿Qué ocurrió antes, qué ocurre ahora y qué puede ocurrir después? |
| Evidencia | ¿Qué documento, mensaje, pago, testigo o hecho puede demostrarlo? |
| Territorio | ¿Qué país, estado, municipio, autoridad o contrato gobierna? |
| Regla | ¿Qué fuente conecta realmente con esa situación? |
| Alcance | ¿La regla es imperativa, disponible, condicionada o excepcional? |
| Límite | ¿Qué no puede concluirse con los datos disponibles? |
| Pregunta | ¿Qué debe aclararse antes de actuar? |

La velocidad de LegalMente surge de reutilizar esta estructura, no de saltarse sus verificaciones. La claridad surge de separar lo que sabemos, lo que inferimos y lo que todavía no podemos afirmar.

## El contrato como unidad humana

Un contrato funciona cuando las personas pueden entender qué deben hacer, qué pueden esperar, qué sucede si algo falla y qué parte no puede cumplirse legalmente. Por eso toda explicación contractual debe buscar tres cosas: el compromiso, la capacidad real de cumplirlo y el límite que ninguna firma puede borrar.

La firma es una evidencia posible, no una explicación completa. La validez de una relación también depende del consentimiento, el objeto, la capacidad, la forma, la conducta posterior, el territorio, la fuente aplicable y la posibilidad real de cumplimiento.

## La diferencia que protege el sistema

LegalMente debe distinguir siempre entre:

| Categoría | Tratamiento |
|---|---|
| Imperativo | No se presenta como renunciable por simple acuerdo. |
| Disponible | Se explica como espacio de pacto dentro de sus límites. |
| Condicionado | Se muestran los hechos que deben confirmarse. |
| Territorial | Se identifica la jurisdicción y no se universaliza. |
| Desconocido | Se conserva como `unknown` y se convierte en pregunta. |
| Profesional | Se deriva a revisión calificada cuando la decisión o el expediente lo exige. |

> El desconocido no es un hueco que deba rellenarse. Es una señal de diseño.

## El sistema visual

Una imagen de LegalMente debe mostrar una tensión humana, no decorar una ley. Antes de generar, se construye una huella con diez ejes:

`world + legalDomain + concept + visualSchool + scenario + revelation + framing + humanPresence + brandObject + dominantPalette`

La imagen sólo pasa si la combinación no existe, si no repite la escuela visual reciente y si modifica suficientes dimensiones del historial. Una nueva frase o un nuevo color no convierten una composición repetida en una imagen nueva.

La dirección correcta es:

> **Pregunta humana → tensión → metáfora causal → escena única → material → luz → encuadre → arquitectura tipográfica → marca integrada → huella registrada.**

La marca “LegalMente” debe vivir dentro de un objeto real de la escena. No debe ser un watermark, un logo flotante ni un overlay genérico. El texto debe ser exacto, legible y verificable.

## El Atlas cultural

El cine, la literatura, la filosofía, la tecnología y la vida contemporánea son puertas de entrada. No son prueba de un caso real. La ruta correcta es:

> **Referencia cultural → conducta observable → conflicto → regla verificable → límite → pregunta cotidiana → herramienta segura.**

La historia despierta interés; la fuente determina el alcance. Una obra no sustituye un artículo. Un personaje no demuestra un hecho. Una metáfora no es un precedente.

## Estados que nunca deben confundirse

| Estado | Significado |
|---|---|
| `READY_FOR_PRODUCT` | Puede trabajarse dentro del producto con los límites declarados. |
| `INTERNAL_REVIEW_ONLY` | Puede explorarse internamente, pero no publicarse. |
| `FOUNDER_LITERALITY_PENDING` | Falta confirmación humana de copy y literalidad. |
| `HOLD_SOURCE` | La fuente, territorio o vigencia no están cerrados. |
| `CURATION_READY` | La pieza está lista para curación, no publicada. |
| `LIVE` | Sólo después de los gates explícitos y evidencia suficiente. |

Nunca se debe interpretar `READY_FOR_PRODUCT` como permiso de publicación. Nunca se debe convertir una ruta interna en pública sólo porque compila.

## El protocolo para el siguiente agente

El siguiente agente debe comenzar leyendo este documento, el mapa de continuidad, el readiness de herramientas, el sistema de rotación visual y el último handoff. Después debe comprobar el estado real de Git y Drive. No debe confiar únicamente en el resumen de una conversación.

Antes de modificar código, debe responder en un registro breve: cuál es el objetivo, qué fuente lo autoriza, qué territorio gobierna, qué estado tiene, qué no está permitido y cómo se verificará. Si falta una respuesta, la tarea pasa a `HOLD` y se formula la pregunta correcta.

Antes de generar una imagen, debe consultar el inventario y registrar la huella propuesta. Antes de publicar una herramienta, debe ejecutar las pruebas de privacidad, integridad, seguridad, rutas públicas, impresión y `git diff --check`. Antes de hacer merge, deploy o publicación, debe comprobar que existe el gate humano correspondiente.

## La promesa de LegalMente

LegalMente debe ser accesible sin ser simplista, riguroso sin ser opaco, humano sin ser sentimental y prudente sin volverse inútil.

Su trabajo no es decirle a cada persona qué sentencia obtendrá. Su trabajo es ayudarle a ver mejor la situación: qué relación existe, qué se prometió, qué se puede probar, qué regla parece relevante, qué no puede darse por hecho y cuál es la pregunta que evita el siguiente error.

> **Ordenar no es reducir la realidad. Ordenar es hacer visible lo que decide.**

Ese es el regalo: una estructura suficientemente simple para moverse rápido y suficientemente rigurosa para no perderse.

## Cierre

Si algún día cambia el agente, el repositorio, el diseño o el equipo, la continuidad no debe depender de recordar quién dijo qué. Debe depender de que la próxima persona pueda seguir la cadena, comprobar la fuente, distinguir el límite y registrar la nueva combinación.

**Así se construye LegalMente: vinculando lo correcto con lo humano, y dejando cada decisión en un lugar donde pueda ser entendida, verificada y continuada.**
